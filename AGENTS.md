# Working agreement

Read PROJECT.md, DESIGN.md, TASKS.md and DOCUMENTATION.md before changes. Work in bounded playable batches; combine related work to test one hypothesis. Keep documentation aligned with implementation. Explain architecture for an experienced programmer learning Godot. Avoid speculative frameworks. Simulation must not depend on scene nodes or artwork. Do not publish or commit unless asked. Preserve user edits. Validate imports and runtime with the installed Godot version; report limitations honestly.

Human editability is a project requirement. Inspect existing architecture before adding systems. Put static visual content and authored layouts in editor-visible scenes; make reusable visual objects reusable scenes. Expose useful tuning parameters through the Inspector. Use scripts for behavior, state and genuinely dynamic content. Reserve procedural construction for content that is actually procedural. Prefer composition and small focused scripts, preserve working behavior, and avoid abstractions without a current use.
